\subsection{React}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.28\textwidth]{Images/Logo/react.png}
    \caption{Logo React}
\end{figure}

\textbf{Giới thiệu}

React là thư viện JavaScript dùng để xây dựng giao diện người dùng theo hướng component hoá. Trong hệ thống SOCO, frontend được xây dựng theo mô hình SPA, giúp điều hướng nhanh và tạo trải nghiệm mượt mà cho các màn hình có nhiều tương tác như newsfeed, marketplace, chat và thông báo.

\textbf{Ưu điểm}
\begin{itemize}
    \item Component hoá tốt, dễ tái sử dụng UI.
    \item Hệ sinh thái phong phú và phổ biến, dễ tìm tài liệu và ví dụ triển khai.
    \item Phù hợp cho ứng dụng nhiều trạng thái và tương tác theo thời gian thực.
\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Không phải framework full-stack, cần kết hợp thêm các thư viện cho routing, state management, data fetching.
    \item Cần kỷ luật kiến trúc để tránh code phân tán khi dự án lớn dần.
\end{itemize}

Trong đề tài, React đảm nhận vai trò xây dựng giao diện chính của hệ thống, hiển thị luồng chức năng cho người mua/người bán và kết nối dữ liệu từ backend thông qua REST API và Socket.IO.

\textbf{Giới thiệu}

TypeScript là ngôn ngữ mở rộng của JavaScript, bổ sung hệ thống kiểu (type system) và các tính năng giúp phát triển ứng dụng quy mô lớn dễ bảo trì hơn. Frontend của SOCO được viết bằng TypeScript để tăng độ an toàn khi định nghĩa kiểu dữ liệu (DTO, state, response API) và giảm lỗi khi mở rộng tính năng.

\textbf{Ưu điểm}
\begin{itemize}
    \item Giảm lỗi runtime nhờ kiểm tra kiểu tại thời điểm biên dịch.
    \item Hỗ trợ refactor tốt và tăng năng suất làm việc nhóm.

\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Tăng độ phức tạp ban đầu do cần khai báo type/interface.
    \item Cần đồng bộ kiểu dữ liệu theo thay đổi của API.
\end{itemize}

Trong đề tài, TypeScript được dùng để định nghĩa kiểu dữ liệu cho các module tính năng, giảm lỗi khi tích hợp API và tăng khả năng bảo trì mã nguồn frontend.

\section{Công nghệ ở Backend}

\subsection{Node.js}

\begin{figure}[h]
    \centering
    \includegraphics[width=0.28\textwidth]{Images/Logo/nodejs.png}
    \caption{Logo Node.js}
\end{figure}

\textbf{Giới thiệu}

Node.js là môi trường runtime cho JavaScript phía server, phù hợp cho ứng dụng I/O nhiều và cần xử lý đồng thời. Backend SOCO chạy trên Node.js để triển khai REST API và Socket.IO.

\textbf{Ưu điểm}
\begin{itemize}
    \item Mô hình non-blocking I/O phù hợp xử lý nhiều request đồng thời.
    \item Đồng nhất ngôn ngữ với frontend, thuận lợi cho phát triển và chia sẻ kiến thức.
\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Cần quản lý tốt cấu trúc dự án để tránh mã nguồn khó kiểm soát khi mở rộng.
\end{itemize}

Trong đề tài, Node.js là nền tảng thực thi cho toàn bộ backend API và luồng real-time.

\subsection{Express.js}

\begin{figure}[h]
    \centering
    \includegraphics[width=0.28\textwidth]{Images/Logo/express.png}
    \caption{Logo Express.js}
\end{figure}

\textbf{Giới thiệu}

Express.js (thường gọi tắt là Express) là framework web tối giản cho Node.js, cung cấp routing và middleware để phát triển ứng dụng web/API. Trong SOCO, Express là nền tảng chính để xây dựng RESTful API và tổ chức mã nguồn theo mô hình MVCS.

\textbf{Ưu điểm}
\begin{itemize}
    \item Tốc độ phát triển nhanh nhờ hệ thống routing và middleware rõ ràng.
    \item Linh hoạt, dễ tích hợp các thư viện bên thứ ba (JWT, validation, upload file, logging\dots).
    \item Phù hợp cho hệ thống API có nhiều module nghiệp vụ.
\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Tính tối giản yêu cầu nhóm tự thiết kế cấu trúc dự án và quy ước code.
    \item Cần cẩn thận trong thiết kế middleware và xử lý lỗi để tránh khó debug.
\end{itemize}

Trong đề tài, Express.js đảm nhận vai trò backend chính, xử lý các nghiệp vụ như quản lý người dùng, bài đăng, sản phẩm, giỏ hàng và đơn hàng, đồng thời làm lớp tích hợp tới Prisma, Cloudinary và các dịch vụ ngoài.

\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Cần thiết kế index và truy vấn hợp lý để tối ưu hiệu năng.
\end{itemize}

Trong đề tài, PostgreSQL là CSDL trung tâm lưu trữ và đảm bảo toàn vẹn dữ liệu cho toàn hệ thống.

\subsection{Redis}

\textbf{Giới thiệu}

Redis là hệ thống lưu trữ key-value in-memory thường được dùng cho cache, session, queue hoặc pub/sub. Trong SOCO, Redis được dùng như tầng cache tùy chọn ở core backend để giảm số lần truy vấn PostgreSQL cho các endpoint đọc nhiều.

\textbf{Ưu điểm}
\begin{itemize}
    \item Tốc độ đọc/ghi nhanh nhờ lưu dữ liệu trong bộ nhớ.
    \item Hỗ trợ TTL cho cache key, phù hợp với dữ liệu cần làm mới thường xuyên.
    \item Có thể triển khai độc lập với database chính và tắt/bật bằng cấu hình môi trường.
\end{itemize}

\textbf{Nhược điểm}
\begin{itemize}
    \item Cần thiết kế cache invalidation hợp lý để tránh dữ liệu cũ.
    \item Là thành phần hạ tầng bổ sung, cần cấu hình và giám sát khi triển khai production.
\end{itemize}

Trong đề tài, Redis được tích hợp qua \texttt{backend/src/lib/redis.js} và \texttt{backend/src/lib/cache.js}. Hệ thống cache danh sách/chi tiết sản phẩm, danh sách/chi tiết bài viết, bình luận bài viết và kết quả tìm kiếm; khi bài viết hoặc sản phẩm thay đổi, controller xóa các cache key liên quan theo pattern.

Trong đề tài, Socket.IO đảm nhiệm luồng trao đổi real-time cho chat và cập nhật thông báo tức thời.
